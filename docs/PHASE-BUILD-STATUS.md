## Phase 1 — self-attested authorization mode (exploit tools made reachable)

Adds an operator self-attestation authorization mode so high-risk / exploit-category
tools are **reachable** for bug-bounty / self-directed testing where no client
signs an Ed25519 grant — without weakening scope.

Files:
- `internal/engagement/engagement.go` — `Authorization.Mode` field (`""` /
  `client-grant` default, or `self-attested`); `SelfAttested()` helper; `validate()`
  rejects unknown modes. `authorized_by` + `agreement_ref` still required in both modes.
- `internal/guard/guard.go` — `Guard.selfAttested` snapshotted from the engagement at
  `New()`. Step 3.5 authorization gate is satisfied by attestation **only for in-scope
  targets**; scope (step 1), risk ceiling (step 2), category (step 3), and time window
  (step 4) all still run and still gate. Gating remains on AUTHORITATIVE tool
  metadata, never model-supplied risk/category.
- `internal/guard/authorization_test.go` — new safety tests.
- `cmd/tyto/authorize.go` / `operator.go` / `serve.go` / `wiring.go` — wiring + keygen.

Tested-green:
- `TestSelfAttestedAllowsExploitInScope` — self-attested mode permits an exploit-tier
  action against an in-scope target.
- `TestSelfAttestedOutOfScopeStillDenies` — **critical**: self-attested mode still
  DENIES out-of-scope targets (the scope invariant survives the new mode).
- `TestTamperedScopeFailsVerification` and the full existing guard suite stay green.

## Phase 2 — bug-bounty scope ingestion + autonomous operator shell

Files:
- `cmd/tyto/scopeparse.go` (+ `scopeparse_test.go`) — paste a program's scope/rules
  text; the model extracts in-scope/out-of-scope entries, rate limit, and forbidden
  activities into a single self-attested engagement. NOTHING auto-launches: parsed
  scope is held in `c.pendingScope` and previewed until the operator confirms.
- `cmd/tyto/onramp.go` (+ `onramp_test.go`) — deterministic "pentest/scan/recon
  <target>" intent parsing (no model call to start a run); target regex for
  URL/CIDR/IPv4/hostname/localhost.
- `cmd/tyto/operator.go` (+ `operator_test.go`) — autonomous-operator loop: the local
  model runs ONE shell command at a time on the Kali box, reads output, decides the
  next command. Kept honest by a two-tier shell gate: read-only toolbox commands run
  unattended; mutating/arbitrary commands run ONLY when free-run is explicitly ON,
  otherwise blocked and fed back as an observation.
- `internal/tool/builtin/shell/`, `kerberoast/`, `ldapenum/` — new builtin tools.

Tested-green: `TestNormalizeScopeEntry`, `TestLooksLikePastedScope`,
`TestBuildScopeEngagement_FullScope`, `TestBuildScopeEngagement_NoTargets`,
`TestScopeSummaryPreviewsAndDoesNotLaunch` (confirms preview does NOT launch),
`TestOperator_RunsReadOnlyAndFinishes`, `TestOperator_BlocksMutatingWhenLockedDown`,
`TestOperator_FreeRunAllowsMutating`.

## Phase 4 — planner ranking, WSL/Kali exec backend, submission reports, AD creds

Files:
- `internal/methodology/methodology.go` + `catalog.json` — techniques ranked so the
  planner sees highest-VALUE first (exploitation/vuln-analysis over recon); within a
  phase, fast native Go tools sort before slow Kali shell-outs (`slowTool`); `webcrawl`
  treated as a gateway that unlocks injection tools. Fixes the slow local model
  burning early cycles on recon.
- `internal/tool/adapter/adapter.go` (+ `backend_test.go`) — `Configure(spec)` /
  `Backend()` execution backend: `""` runs on host, `wsl:<distro>` wraps every
  shelled-out command with `wsl -d <distro> --`. Unknown spec fails loudly at boot.
- `internal/engine/engine.go` — injects provisioned domain credentials into
  `ldapenum` / `kerberoast` when the planner didn't supply them (planner params win).
- `internal/report/submission.go` (+ `submission_test.go`), `report.go`,
  `htmlreport.go`, `state/finding.go` — `Submission`: triaged, deduplicated,
  submission-grade projection (CVSS, affected targets, repro steps, impact, evidence)
  with likely-noise foregrounded separately.
- `internal/planner/prompt.go`, `internal/tool/builtin/{dirfuzz,portscan}` — supporting
  prompt/tool tweaks.

Tested-green: `TestConfigureAndWrap` (host identity + WSL prefix wrapping),
`TestRenderSubmissionDedupsAndShowsFields`, `TestBuildSubmissionCVSSDerived`,

## REMAINING / needs live verification

### Phase 3 — full exploitation chaining + impact proof (NOT built)
- Exploit-category tools are now **reachable** via Phase 1's self-attested mode
  (the authorization gate no longer blocks them for in-scope targets), and the
  operator loop (Phase 2) can drive the Kali toolbox one command at a time.
- **Not built:** autonomous exploit-and-prove-impact — chaining a discovered vuln
  through to a demonstrated impact artifact (e.g. extracted data / proof token /
  callback) automatically, and the conversational request-replay / fuzz capability
  (interactively re-sending and mutating a captured request to confirm and weaponize
  a finding). These remain manual/operator-driven for now.

### Phase 5 — breadth-first scale, concurrency, GPU/remote-ollama performance (NOT built)
- No breadth-first scaling across many targets, no run-level concurrency tuning, and
  no GPU / remote-ollama performance path. Today the local model is CPU-only and slow;
  the methodology ranking (Phase 4) is a mitigation, not a substitute for real
  parallelism or faster inference.
